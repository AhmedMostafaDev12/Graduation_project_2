backend-ai · development plan

Remori backend plan

The order the backend gets built in: the database goes live first, and the API is deployed early with seeded data, so Flutter and the phone relay integrate from the start instead of at the end.

Decisions this plan follows (lead, 11 Oct 2026)

  • Mock data = seeded database. CRUD endpoints are real and read/write the live database, filled with the UI board's sample data. Only AI-dependent endpoints return fixed answers ("AI stubs") until the AI layer exists.
  • Real auth from the first deploy: login, JWT, device token and patient-link authorization.
  • Production as in the course (fastapi-course repo): nginx + certbot (HTTPS) + ufw on the Ubuntu host, gunicorn with 2 uvicorn workers serving the app. The app runs in Docker bound to 127.0.0.1:8000. Domain: remori-ai.duckdns.org.
  • Manual deploy: SSH into EC2 → git pull → docker compose up -d --build. CI stays "PR checks only".

4.1 Firewall (ufw)sudo ufw allow OpenSSH → sudo ufw allow 'Nginx Full' → sudo ufw enable. The AWS security group stays as a second layer.

4.4 docker-compose.ymlapi from the Dockerfile, running gunicorn with 2 uvicorn workers. Ports "127.0.0.1:8000:8000" only (Docker bypasses ufw). restart: unless-stopped, env_file: .env.

4.6 Deploy proceduressh → cd ~/remori → git pull → docker compose up -d --build → alembic upgrade head (in the api container) → smoke test. Documented in backend-ai/README.md.
